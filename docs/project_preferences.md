# Project Preferences

This file stores durable preferences for maintaining the `charlie-project-stewardship` plugin itself.

## Confirmed Rules

- Keep rules, but do not turn them into a cage that reduces model reasoning or initiative.
- Put outcomes, true invariants, approval boundaries, and success evidence in the foreground; leave
  implementation paths to the Agent when several safe paths are valid.
- Keep the default capability surface small and progressively disclose references or tools.
- Prefer repository evidence and native host capabilities over a stale hard-coded tool catalog.
- Prefer deterministic tests/scripts for repeated objective checks and keep prose for judgment.
- Preserve existing project structure and design systems unless the request or evidence supports a
  change; source recipes and platform-native guidance are optional inputs.
- Never overwrite existing project files by default, read real secrets, escape the target root, or
  imply authorization for installation/push/deploy.
- Treat browsers, semantic indexes, and output compression as optional adapters.
- Evaluate real task success, unnecessary questions/tool loops, context cost, verification quality,
  and unauthorized-action rate—not template count or a self-defined readiness score.
- Keep legacy Skill and CLI entry points compatible while steering new use toward the five focused
  capabilities.
